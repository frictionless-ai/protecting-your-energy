# Token Guide

Reduce avoidable effort while delivering the requested outcome. Apply a suggestion when its conditions fit the current work. Current user instructions, required source coverage, ownership and acceptance criteria determine the task.

## Context and investigation

1. Batch calls whose inputs are already known and whose results are independent.
2. Retain a compact continuation at a natural transition when context becomes unwieldy.
3. Reuse prior source investigation and hand forward its exact references and limitations.
4. Locate the relevant symbol or section before choosing a read extent. Read complete relevant exchanges or documents when the request requires that coverage.
5. Keep large optional references proportional to the current phase.
6. Extract the fields, ranges and counts needed for a decision while keeping the full original available.
7. Inspect a large file's headings or index before paging through it.
8. Check known tool, skill and project locations before broad filesystem searches.
9. Reference reusable text by path when the executor can access that file and still receives the context it needs.

## Execution and delegation

10. Continue independent authorized work while an actual operation is running. Retain its handle and completion condition.
11. Use the host's real background and waiting mechanisms for long work. Poll according to the operation and its expected duration.
12. Parallelize independent units with explicit file ownership and isolation where needed.
13. Give workers a goal, owned files, constraints, verification method and a concise return format.
14. Select the relevant workflow for the current phase without repeatedly loading unrelated process material.
15. Match worker models and reasoning to the task using applicable routing instructions.
16. Preserve the original outcome when the user asks to implement. Resolve real dependencies and then execute the authorized work.
17. Inspect where a tool expects input before generating files or scripts for it.
18. Keep commands understandable and avoid fragile chains that make failure attribution difficult.
19. Inspect related branch state together when the decision needs that comparison.

## Verification and recovery

20. Verify the actual result and its normal entry point. Repeating the same broad check requires a relevant change, failure or remaining concern.
21. Match review depth to complexity and risk. Keep independently useful passes when the task calls for them.
22. Preserve authoritative source work, changes made by others and partial results through retries.
23. Diagnose a timeout, malformed pattern or failed collection before repeating the same command.
24. Use text inspection for text questions and visual inspection when appearance or interaction matters.
25. Measure time, resource use and extra owner work before claiming an efficiency improvement.

The hook offers one or two short hints with cooldowns. Treat them as provisional observations, and keep doing the work when a suggestion does not fit. Disable hints with `TOKEN_GUIDE_OFF=1` when appropriate.
