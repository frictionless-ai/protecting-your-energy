# Additional local writing and intent workflows

These portable local variants add acceptance-criteria preparation, UI copy, existing-prose editing, author-voice drafting and requested repository-metadata review.

| Skill | Role |
| --- | --- |
| `intent-driven-development` | Recover context and define observable acceptance criteria at an appropriate depth. |
| `plain-ui-copy` | Write short UI text and audience-appropriate documentation. |
| `voice-match` | Edit existing prose using the task and optional private author profile. |
| `write-as-me` | Draft new prose for the requested author and audience. |
| `no-ai-fingerprint` | Review unwanted generated-writing conventions and authorized metadata changes. |

The source family contained personal voice banks, counted corpus budgets, registers and evolution logs. Those files remain private at their original locations. `PYE_VOICE_PROFILE_DIR` can point to an authorized local configuration. Templates show the expected fields without supplying a personal profile.

The voice diagnostic helper accepts `--profile PATH` for private JSON register budgets. It reports `UNPROFILED` when no active budget is configured. Its counters support editing decisions and cannot establish authorship or semantic fidelity.

These variants came from local installed instructions. The private integration map retains source and destination hashes. Intent-driven-development has unresolved original provenance. Owner-specific customization in the writing family establishes local changes, while any later upstream attribution or license finding must be retained.

Profile access and source recovery stay within the task's authorized scope. Git-history rewriting, force pushes, external profile creation and outbound messages retain their existing authorization requirements.
