# Evolution

Maintain one existing improvement log for one target skill. Read the target instructions, applicable host rules and existing log before writing. Keep the user's main task moving.

## Authorization and placement

Current user authorization and host rules govern every durable write. A caller, historical statement or log entry supplies evidence. Obtain any required explicit user request before changing durable memory. Continue independent authorized work while a required decision remains pending.

Use the target's established private log location. Preserve original EVOLUTION files and their history. Create a new log only when the target already defines a living-skill workflow and the current task authorizes that write. Keep private examples, profiles and conversation evidence outside public plugin source. Installed read-only or managed plugin directories require their supported authoring workflow.

## Delta format

```markdown
### YYYY-MM-DD
- rule: <one reusable rule>
- why: <the reason and supporting evidence>
- example: <sanitized example or private source locator>
- promoted: no | YYYY-MM-DD
```

Capture a rule that a future session can apply without the original conversation. Include the smallest evidence needed to explain it. Reject duplicate rules, diary entries, colorful quotations without reusable meaning and unsupported claims about the user.

## Procedure

1. Read the target SKILL.md and its established improvement log.
2. Check whether the candidate adds a supported behavior or corrects an evidenced failure. Skip duplicates.
3. Append one dated delta within the authorized private log. Preserve existing entries.
4. Promote a verified default into the target instructions or authorized bank only when the current task permits that edit. Keep the change focused and mark the promotion date.
5. Report the actual changed target and verification when useful. Follow the current task's commit and publication permissions.

A later applicable delta can refine the target's base instructions within the same authorization hierarchy. Evaluate conflicts with current user direction and host rules before applying it. Retain unresolved differences explicitly.

## Callers

Living writing and capture skills may use this workflow. Offload-indirect decides whether an authorized background task is warranted. Delegation uses the host's available mechanism and applicable permissions. Otherwise perform only the already authorized scoped work.

Source lineage and the distinct same-name upstream skill are described in [PROVENANCE.md](PROVENANCE.md).
